# 智能记账 · 规则包发布操作手册

> 适用：运营/管理员通过授权服务后台发布“业务模板规则包”，客户端拉取并验签生效。
> 相关文档：《智能记账-业务模板定义手册.md》（模板字段怎么写）。

---

## 1. 规则包是什么

规则包 = **一组业务模板（scenarios）** 打包后，由服务端用私钥**签名**得到的数据：

```
{ "type": "rulepack", "version": "2026.11.1", "scenarios": [ ...模板对象... ] }
        │ 服务端用 SV_PRIVATE_KEY 签名
        ▼
SV1.<base64url(payload)>.<base64url(signature)>   ← 客户端拉取的就是它
```

- 客户端内置**公钥**，拉取后验签；验签通过才加载。
- 模板只负责“关键词 → 借贷分录”，具体字段见《业务模板定义手册》。

加载优先级（客户端）：**内置模板 < 下载的规则包 < 用户自定义模板**。

---

## 2. 前提检查

1. 授权服务已启动：`pm2 status` 中 `sv-license` 为 online。
2. 服务端已配置与客户端公钥配对的私钥：`/opt/sv-license/sv.env` 的 `SV_PRIVATE_KEY`。
3. 已知管理令牌 `ADMIN_TOKEN`（也在 `sv.env`）。
4. 客户端「智能录入 → LLM 设置」中的“规则包地址”指向：
   `https://weve.pyrelle.asia/api/rulepack`（默认已内置）。

验证服务端在线：
```bash
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8081/admin
```

## 3. 三步发布

### 第 1 步：打开管理后台
浏览器访问 `https://weve.pyrelle.asia/admin`，在顶部填入 `ADMIN_TOKEN`（会保存在本浏览器）。

### 第 2 步：填写版本 + 场景 JSON
在「规则包发布」区域：
- **版本**：如 `2026.11.1`（见第 4 节版本规范）。
- **场景 JSON**：一个**数组**，元素是业务模板对象（可多个）。

示例（“用户充值 + 支付平台佣金”两个模板）：
```json
[
  {
    "id": "custom_user_recharge",
    "name": "用户充值",
    "keywords": ["充值", "用户充值", "会员充值"],
    "direction": "in",
    "category": "sale",
    "amount_tax": "inclusive",
    "tax": { "mode": "output" },
    "settlement": [
      { "when": ["现金"], "account": "1001" },
      { "default": true, "account": "1002" }
    ],
    "entries": {
      "general": [
        { "side": "debit",  "account": "{{settlement}}", "amount": "total" },
        { "side": "credit", "account": "6001", "amount": "net" },
        { "side": "credit", "account": "2221", "amount": "tax" }
      ],
      "small": [
        { "side": "debit",  "account": "{{settlement}}", "amount": "total" },
        { "side": "credit", "account": "6001", "amount": "net" },
        { "side": "credit", "account": "2221", "amount": "tax" }
      ]
    }
  },
  {
    "id": "custom_platform_commission",
    "name": "支付平台佣金",
    "keywords": ["佣金", "平台佣金", "支付佣金"],
    "direction": "out",
    "category": "expense",
    "tax": { "mode": "none" },
    "settlement": [
      { "when": ["现金"], "account": "1001" },
      { "default": true, "account": "1002" }
    ],
    "entries": {
      "general": [
        { "side": "debit",  "account": "6601", "amount": "total" },
        { "side": "credit", "account": "{{settlement}}", "amount": "total" }
      ],
      "small": [
        { "side": "debit",  "account": "6601", "amount": "total" },
        { "side": "credit", "account": "{{settlement}}", "amount": "total" }
      ]
    }
  }
]
```

> 更多模板（采购、费用、借款、缴税、预收充值等）见《业务模板定义手册》第 9 节，直接把需要的对象追加到数组里。

### 第 3 步：签名并发布
点「签名并发布」。成功后页面显示“已签名并发布版本 x.y.z”。

> 也可用「上传 Token」：粘贴一个**已签名**的规则包 Token（`SV1....`）。需同时填版本号；Token 必须由与客户端公钥配对的私钥签名。

### 方式一：离线签发（可选）

当你不希望把私钥放在服务器、或想在 CI/受控环境完成签名时，用离线工具生成 Token，再在后台「上传 Token」发布。

1. **准备场景文件**（模板数组），可参考 `tools/rulepack.example.json`。

2. **签发**：
   ```bash
   python3 tools/mint_rulepack.py \
     --version 2026.11.1 \
     --scenarios tools/rulepack.example.json \
     --out rulepack.token
   ```
   私钥来源（优先环境变量）：
   - `SMART_VOUCHER_PRIVATE_KEY`（64 位 hex），或
   - 文件 `tools/.smart_voucher_private_key`。

   不传 `--out` 时，Token 直接输出到 stdout（便于 CI 管道）。

3. **校验**：
   ```bash
   python3 tools/mint_rulepack.py --verify rulepack.token
   ```
   输出示例：
   ```json
   {
     "type": "rulepack",
     "version": "2026.11.1",
     "scenario_count": 2,
     "scenario_ids": ["custom_user_recharge", "custom_platform_commission"],
     "public_key": "adaa8483af462e8380ba881d3a81c20094d7ce0af190967a722cecdb3e6b3353"
   }
   ```
   - `public_key` 必须等于客户端内置公钥：`adaa8483af462e8380ba881d3a81c20094d7ce0af190967a722cecdb3e6b3353`。

4. **发布**：后台「规则包发布 → 上传 Token」粘贴 `rulepack.token` 内容；**版本号手动填成与 Token 内一致**（`2026.11.1`）。

5. **客户端更新**：「智能录入 → 更新规则包」。

> 注意：
> - 上传 Token 时服务端**不会**解析 Token 内的版本，后台“版本”字段需你手动填一致。
> - 当前 License 与规则包共用同一把私钥；若要让私钥完全不进服务器，应改造为**两把独立密钥**。
> - 依赖：`pip install cryptography`；私钥务必离线保管、`chmod 600`、勿入仓库。

---

## 4. 版本规范

- 建议 `YYYY.MM.N`（如 `2026.11.1`）或语义化版本；**单调递增**便于排查。
- 当前客户端行为：拉取成功后**直接安装并覆盖**本地规则包，**不比较版本高低**。
  - 因此“回滚”= 用旧内容发布一个新版本（见第 7 节）。
- 服务端 `GET /api/rulepack` 永远返回**最新发布**（按入库 id 倒序）。

## 5. 发布后验证

### 5.1 服务端
```bash
# 公开接口：应返回 200 + version/token
curl -sS -i https://weve.pyrelle.asia/api/rulepack

# 管理接口：查看历史发布
curl -sS -H 'X-Admin-Token: 你的ADMIN_TOKEN' https://weve.pyrelle.asia/api/admin/rulepacks
```

### 5.2 客户端
「智能录入 → 更新规则包」→ 成功后按钮旁显示：
`规则包 2026.11.1 · N 条`

本地文件（桌面端）：
```
<用户数据目录>/small-business-manager/modules/smart_voucher/
  ├─ rulepack.token        # 签名后的规则包
  └─ rulepack_meta.json    # version / installed_at / scenario_count
```
- macOS：`~/Library/Application Support/small-business-manager/modules/smart_voucher/`
- Windows：`%APPDATA%\small-business-manager\modules\smart_voucher\`

### 5.3 生效验证
在「智能录入」输入一句命中新模板的话（如“今天用户充值 10 元”）→ 预览里 `场景名` 应显示对应模板名。

## 6. 编写场景 JSON 的注意事项

- 必须是**合法 JSON 数组**（`[ {...}, {...} ]`），不能有注释、不能有尾逗号。
- 每个模板 `id` 唯一；自定义建议 `custom_` 前缀，避免与内置冲突。
- 关键词避免过泛：
  - “佣金”不要用“手续费”（与内置“银行手续费”冲突）。
  - “充值”不要与“服务费”混用。
- 用到的**科目代码必须已存在**（如 `6601`、`6001`、`2202`；预收需先建 `2203`）。
- 小规模与一般纳税人分录分别写在 `entries.small` / `entries.general`；小规模进项不抵扣（`small` 用 `total`）。
- 净额结算（充值 10、佣金 0.09、银行只到账 9.91）当前引擎限制见模板手册第 10 节。

---

## 7. 回滚与灰度

- **回滚**：把旧版本的 scenarios 内容用新版本号重新发布一次（客户端会覆盖为旧内容）。
- **灰度**：当前服务端只维护“最新一个包”，没有按客户分组灰度。
  - 若需要灰度/分渠道，需升级服务端：按客户/渠道返回不同规则包（后续可加）。
- 建议保留每次发布的 `scenarios` 原文（导出/存档），便于回滚。

## 8. 自动化发布（可选）

用 curl 直接调用管理接口（等价于后台操作）：

```bash
cat > rulepack.json <<'JSON'
{
  "version": "2026.11.1",
  "scenarios": [
    { "id": "custom_demo", "name": "演示", "keywords": ["演示"],
      "direction": "out", "tax": { "mode": "none" },
      "settlement": [{ "default": true, "account": "1002" }],
      "entries": {
        "general": [
          { "side": "debit", "account": "6602", "amount": "total" },
          { "side": "credit", "account": "{{settlement}}", "amount": "total" }
        ],
        "small": []
      }
    }
  ]
}
JSON

curl -sS -X POST https://weve.pyrelle.asia/api/admin/rulepack \
  -H 'X-Admin-Token: 你的ADMIN_TOKEN' \
  -H 'Content-Type: application/json' \
  --data-binary @rulepack.json
```

> CI 场景：可先用 `tools/mint_rulepack.py` 离线生成 `token`，再以
> `{"version":"2026.11.1","token":"SV1..."}` POST 到同一接口（服务端只存储分发，无需私钥）。
> 示例：
> ```bash
> TOKEN=$(python3 tools/mint_rulepack.py --version 2026.11.1 --scenarios scenarios.json)
> jq -n --arg v 2026.11.1 --arg t "$TOKEN" '{version:$v, token:$t}' \
>   | curl -sS -X POST https://weve.pyrelle.asia/api/admin/rulepack \
>       -H 'X-Admin-Token: 你的ADMIN_TOKEN' -H 'Content-Type: application/json' --data-binary @-
> ```

## 9. 安全要求

- `SV_PRIVATE_KEY` 只放服务端，绝不入客户端/仓库；泄露即任何人可伪造规则包与 License。
- `ADMIN_TOKEN` 使用强随机串，后台务必走 HTTPS。
- 规则包本身是公开可下载的（客户端要拉取），安全性靠**签名**保证，不靠保密。
- 不要发布含客户敏感信息的场景（模板是分发给所有用户的）。

## 10. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| App 更新时报 `服务器返回 404 Not Found` | **还没发布过规则包**；先按第 3 节发布一个 |
| 后台发布返回 `缺少 version` | 版本号为空 |
| 后台发布返回 `sign: 缺少 SV_PRIVATE_KEY` | 服务端 `sv.env` 未配置私钥，或改后未 `pm2 restart sv-license` |
| App 更新报“签名无效” | 服务端私钥与客户端内置公钥不配对 |
| 更新成功但模板不生效 | 检查关键词是否命中、是否被更具体的内置模板抢走、科目代码是否存在 |
| 发布后接口仍返回旧版本 | 客户端点“更新规则包”重新拉取；服务端确认 `GET /api/rulepack` 已是新版本 |
| 模板写错导致整包无效 | 规则包内任一模板需可解析；先在后台小批量发布验证 |
