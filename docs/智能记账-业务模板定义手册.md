# 智能记账 · 业务模板定义手册

> 适用：小微企业管理助手「智能录入」模块
> 目的：让你不看代码，也能自己写出/修改业务模板。
> 说明：本手册对应当前解析引擎的行为；存在少量限制（见第 10、11 节）。

---

## 1. 一句话理解

一个**业务模板**就是一条规则：

> 用户输入里出现某些**关键词**、有一个**金额** → 系统按模板生成一组**借贷分录**。

系统实际做的事：
1. 把一句话按标点拆成多笔（`，。；、换行`、以及「另外/还有/以及/同时」）。
2. 每笔里识别**日期**和**金额**。
3. 用关键词去匹配模板，命中的模板负责生成分录。
4. 分录里再用 `total / net / tax` 算具体金额。

---

## 2. 一分钟上手

最小可用模板（收到现金/银行存款的服务费）：

```json
{
  "id": "custom_service_fee",
  "name": "收取服务费",
  "keywords": ["服务费", "咨询费"],
  "direction": "in",
  "category": "sale",
  "amount_tax": "inclusive",
  "tax": { "mode": "output" },
  "settlement": [
    { "when": ["现金"], "account": "1001" },
    { "default": true, "account": "1002" }
  ],
  "entries": {
    "general": [
      { "side": "debit",  "account": "{{settlement}}", "amount": "total" },
      { "side": "credit", "account": "6001", "amount": "net" },
      { "side": "credit", "account": "2221", "amount": "tax" }
    ],
    "small": [
      { "side": "debit",  "account": "{{settlement}}", "amount": "total" },
      { "side": "credit", "account": "6001", "amount": "net" },
      { "side": "credit", "account": "2221", "amount": "tax" }
    ]
  }
}
```

添加方式：
- 只给自己/某客户用：App「智能录入 → 业务模板管理」粘贴保存。
- 给全部用户：授权服务后台 `/admin` 的「规则包发布」，把模板放进 `scenarios` 数组，填新版本 → 发布；客户端「更新规则包」。

## 3. 字段总览

| 字段 | 必填 | 类型 | 作用 |
|---|---|---|---|
| `id` | 是 | 字符串 | 模板唯一标识（自定义时勿与内置冲突，建议 `custom_` 前缀） |
| `name` | 是 | 字符串 | 展示名称 |
| `keywords` | 是 | 字符串数组 | 命中关键词 |
| `direction` | 否 | `in` / `out` | 收/付方向（当前仅描述性，用于理解与后续扩展） |
| `category` | 否 | 字符串 | 业务分类（仅描述性，如 `sale`/`purchase`/`expense`） |
| `amount_tax` | 否 | `inclusive` | 金额口径，当前引擎按**含税**处理（保留字段） |
| `tax` | 否 | 对象 | 税额策略 `{ "mode": "output|input|none", "rate": 0.03 }` |
| `settlement` | 否 | 数组 | 结算科目规则（现金/银行/未付…） |
| `entries` | 是 | 对象 | 分录模板，分 `general`（一般纳税人）与 `small`（小规模） |
| `priority` | 否 | 整数 | 同分时的优先级，越大越优先 |
| `version` | 否 | 整数 | 模板版本（仅描述） |

---

## 4. 字段详解

### 4.1 id / name / version
- `id` 唯一。**一旦被学习样本引用，尽量不要改 id**，否则历史学习失效。
- 自定义建议：`custom_xxx`。
- 内置模板 id 列表见第 9 节，避免重复。

### 4.2 keywords（关键词）
- 命中即可匹配；**关键词越长、命中越多，得分越高**。
- 匹配是「包含」关系（`lower.contains(keyword)`），不需要整句相等。
- 冲突处理：避免用太通用的词（如“费用”“服务费”），否则会抢别的模板。常用做法：
  - 佣金类用 `佣金 / 平台佣金 / 支付佣金`，不要用 `手续费`（已被“银行手续费”占用）。
  - 充值类用 `充值 / 用户充值 / 会员充值`。

### 4.3 direction / category
- 目前**不参与分录生成**，仅作说明。分录由 `entries` 决定。
- 建议按实际填写，便于日后扩展与 LLM 参考。

### 4.4 amount_tax（金额口径）
- 当前引擎一律把识别到的金额当作**含税总额**。
- `amount_tax` 为保留字段；填 `inclusive` 即可。

### 4.5 tax（税额策略）
```json
"tax": { "mode": "output", "rate": 0.03 }
```
- `mode`：
  - `output`：销售类，产生销项税（收入=总额/(1+税率)，税=总额−收入）。
  - `input`：采购/费用类。**一般纳税人**可拆进项税；**小规模纳税人进项不抵扣**（引擎自动按 `small` 变体全额入成本/费用）。
  - `none`：不涉及增值税（借款、还款、缴税、手续费、利息、佣金等）。
- `rate`（可选）：覆盖默认税率。
  - 小规模默认 `0.03`（可用设置 `small_vat_rate` 改）。
  - 一般纳税人默认取设置 `vat_rate`（常用 0.13）。
  - 服务类可按需在模板里写 `"rate": 0.06`。

### 4.6 settlement（结算科目）
```json
"settlement": [
  { "when": ["未付", "赊", "欠", "应付"], "account": "2202" },
  { "when": ["现金"], "account": "1001" },
  { "default": true, "account": "1002" }
]
```
- 从上到下匹配：某条 `when` 里的词出现在句子中即采用该 `account`。
- 没命中任何 `when` 时，用 `default: true` 的那条。
- 建议最后总有一条 `default`。
- 分录里用 `{{settlement}}` 引用选中的科目代码。

### 4.7 entries（分录模板）
```json
"entries": {
  "general": [ { "side": "debit", "account": "1403", "amount": "net" }, ... ],
  "small":   [ { "side": "debit", "account": "1403", "amount": "total" }, ... ]
}
```
- `general`：一般纳税人使用；`small`：小规模纳税人使用。
- 判断依据：设置 `taxpayer_type` 含「小规模」即走 `small`（为空也按小规模）。
- 若 `small` 为空，则回退用 `general`。
- 每个分录项：
  - `side`：`debit`（借）或 `credit`（贷）。
  - `account`：科目代码，或占位符 `{{settlement}}`。
  - `amount`：`total` / `net` / `tax`（见第 5 节）。

### 4.8 priority（优先级）
- 计分从 `priority` 起，关键词命中再加分；同分时 `priority` 大的胜出。
- 一般留空或 `0`；只有出现匹配冲突时才需要调整。

## 5. 金额表达式

设识别到的金额为 `total`（含税），税率为 `rate`：

| 表达式 | 含义 | 是否含税判断 |
|---|---|---|
| `total` | 原金额 | 总是 |
| `net` | `total / (1 + rate)` | 只有当 `tax_applies` 为真时；否则等于 `total` |
| `tax` | `total − net` | 只有当 `tax_applies` 为真时；否则为 `0` |

`tax_applies`（是否计税）：
- `mode = output` → 计税。
- `mode = input` → 一般纳税人计税；小规模**不计**（进项不抵扣）。
- `mode = none` → 不计。

金额会四舍五入到 2 位小数；若借贷出现几分钱误差，引擎会自动在某一方做平衡调整。

## 6. 增值税处理速查

| 纳税人 | mode=output（销售） | mode=input（采购/费用） | mode=none |
|---|---|---|---|
| 一般纳税人 | 借银行总额 / 贷收入(净) / 贷销项税 | 借成本(净) / 借进项税 / 贷银行总额 | 不拆税 |
| 小规模 | 借银行总额 / 贷收入(净) / 贷应交增值税 | **不拆税，全额入成本/费用** | 不拆税 |

> 小规模进项不抵扣是刻意设计；`small` 变体里用 `amount: "total"` 即可。

## 7. 解析规则（你需要知道的输入习惯）

### 7.1 日期
支持：`今天 / 今日 / 昨天 / 昨日 / 前天`、`YYYY-MM-DD`、`YYYY/MM/DD`、`YYYY年MM月DD日`、`M月D日`。
- 未写日期时，使用「基准日期」（默认今天，可在界面选择）。
- 一条描述里若只有第一句写了“今天”，其余子句会各自使用基准日期。

### 7.2 金额
- 优先取带单位 `元 / 块 / 万` 的数字（`万` 会 ×10000）。
- 否则取句中最后一个数字。
- 日期里的数字会先被剔除，不会被误当金额。

### 7.3 拆句
- 按 `，,。；;、换行` 以及 `另外 / 还有 / 以及 / 同时` 拆成多个子句。
- **每个子句生成一张凭证**（多笔 → 多张）。

示例：
```
今天用户充值 10 元，缴纳支付平台佣金 0.09 元
```
→ 拆成 2 笔：
1. 今天用户充值 10 元
2. 缴纳支付平台佣金 0.09 元（没写日期 → 基准日期）

## 10. 净额结算的限制（重要）

当前引擎**每个子句只识别一个金额**，所以：

- 若银行流水是**两笔**（充值 +10、佣金 −0.09）→ 用两个模板、输入两句话，生成两张凭证，正确。
- 若平台**直接扣佣、银行只到账净额 9.91** → 正确做法是**一张三分录凭证**：
  ```
  借 银行存款 9.91
  借 销售费用-佣金 0.09
  贷 主营业务收入 10.00
  ```
  这种“总额 − 佣金 = 净额”的自动生成，当前模板模型**做不到**（它只有一个 `total`）。
  现阶段处理：
  1. 手工录这张凭证；或
  2. 等引擎升级支持“第二个金额 / 扣费字段（fee）”。（这是规划中的增强）

## 12. 新增 / 更新 / 分发

### 12.1 单机/单客户
「智能录入 → 业务模板管理」→ 粘贴 JSON → 保存。内置模板不可删除，自定义可删除。

### 12.2 全量分发（规则包）
授权服务后台 `/admin` →「规则包发布」：
- 方式一：填 `version` + `scenarios`（数组，放多个模板对象）→ 服务端签名发布。
- 方式二：粘贴已签名的规则包 Token。
客户端「更新规则包」后生效；加载优先级：内置 < 规则包 < 用户自定义。

## 13. 校验与排错

| 现象 | 原因 / 处理 |
|---|---|
| 预览里科目名称为空、生成报“科目不存在” | 用了不存在的科目代码；先在「科目管理」新增 |
| 提示“未匹配业务类型” | 关键词没命中；加更具体的关键词，或检查错别字 |
| 提示“无法识别金额” | 句子里没有数字/金额单位；补金额 |
| 借贷不平衡 | 模板分录写错；检查 `side` 与金额表达式 |
| 税算得不对 | 检查 `tax.mode`、`rate`、纳税人类型设置 |
| 匹配到错误的模板 | 关键词太通用，产生冲突；改用更具体的词或调 `priority` |
| 一段话生成太多/太少凭证 | 检查拆分标点；必要时拆成多行分别录入 |
| 净额/佣金对不上银行 | 见第 10 节限制 |

调试建议：
1. 先用最短句子测试（如“收到服务费 100 元”）。
2. 看预览里的「置信度 / 警告 / 命中的场景名」。
3. 再逐步加入结算方式、日期等。

```text

amount_tax    inclusive

                { "default": true, "account": "1002" } ]
```
